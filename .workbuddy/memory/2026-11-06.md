## 目录二级分组：二次点击收不起来

- 根因：`.toc-lv1` 的 click 只调 `showCh(dataset.ch)`，而 `showCh` 里是
  `g.classList.toggle('open', a.dataset.ch === id)` —— 点当前章节等于「再展开一次」，
  永远收不起来；分组本身根本没有 toggle 逻辑。
- 修法：click 里先判断 `a.dataset.ch === 当前 .chapter.on 的 id`，是就只 `classList.toggle('open')`
  并同步 `aria-expanded`，不再走 `showCh`（否则还会顺带 `scrollTo(0)`）。
- 动画：`display:none` 无法过渡，改成 `grid-template-rows: 0fr → 1fr` + 内层
  `.toc-subs-inner{min-height:0;overflow:hidden}`。代价是要在 8 个 `.toc-subs` 里加一层 wrapper
  （否则多个锚点会各占一行，0fr 只作用于第一行）。
- 收起后子项还能被 Tab 聚焦，用 `visibility:hidden` + `transition: visibility 0s linear .26s`
  延迟到动画结束再生效解决。
- `spy()` 里目录跟随滚动那段要加 `grp.classList.contains('open')` 判断：收起时链接
  `getBoundingClientRect()` 是全 0，会把 `toc.scrollTop` 一路减到顶。

### 无头环境验动画的老坑（重要）

`--virtual-time-budget` 下 **CSS 过渡的时钟不走**：`getAnimations()` 能拿到
`playState=running` 的 transition，但 `currentTime` 永远是 0，`transitionend` 不触发，
量到的 `height` 停在起始值——不要据此判断"动画没生效"。

绕法：拿到 `p.getAnimations()` 后 `pause()`，手动把 `currentTime` 设成 65/130/195/259 再量高度，
得到 170→130→38→7→0 就说明属性真的能插值。截图同理，seek 到 120ms 可以拍到中间帧。

## 16:15 资源版控 + 每次加载清缓存
- 新增 `js/boot.js`（唯一版本号入口，`VERSION = '2026.11.06.1'`）。三页 head 里
  **紧跟 `<link>` 之后**引入：`<script src="./js/boot.js?v=2026.11.06.1">`。
  必须放 link 后面——它靠 `document.querySelectorAll('link[rel=stylesheet]')` 改 href。
- `ALWAYS_FRESH = true`：版本串 = `VERSION + '.' + Date.now()`，每次加载都不同，
  浏览器必然重取 CSS。改成 `false` 就退回"只有改 VERSION 才更新"。
- 脚本没法事后改 src（解析到时已开始加载），所以底部 `<script src>` 全换成
  `document.write('<script src="...?v=' + window.__V + '"><\/script>')`。
  **`<\/script>` 的斜杠必须转义**，否则把当前脚本标签提前闭合。
- 实测代价：CSS 会被请求两次（HTML 里原始 href 一次 + 改 href 后一次），
  第一次基本被取消。想零浪费就得让 link 不带 href 由 JS 赋，会晚一个 RTT 才开下，
  反而更慢，所以接受双请求。
- 清理范围：只删 `ynhhz-cache:` 前缀（project 目前没有这类键，为将来预留）。
  `hzz_session`（登录态）、`ynhhz-fs`（字号）**不能清**——用户明确要求登录态只在手动退出时清。
- HTML 自身缓存 meta 无效（浏览器忽略 http-equiv Cache-Control 对文档的作用），
  上线要在服务端配 `Cache-Control: no-cache`，否则用户拿到的还是旧 DOM。
- 云展页 `云南河湖长制十周年成果云展.html` CSS/JS 全内联，不需要接 boot。

## 11-07 16:00 版控回归：FTP over HTTP 网关不认 query string
- 现象：用户从封面进 `shouce.html#ch1` 变成**完全无样式的裸 HTML**（截图里只剩默认链接和一个撑爆的巨大蓝色圆环），
  点登录、返回首页时"突然闪"一下。
- 根因：`ftp-fun.com:5567` 是 FTP over HTTP 网关，**对带 ? 的地址直接 404**。
  上一轮加的 `js/boot.js` 会给所有 CSS/JS 的 URL 加上 `?v=版本.时间戳`，
  于是 index.css 取不回来 → 浏览器丢弃整张样式表 → 裸 HTML。
  底部业务脚本同样带参 → 404 → 交互全挂。
- 修复：
  1) `js/boot.js` 改成**先探测再决定**：同步 XHR `HEAD <css>?v=...`，
     2xx 才给 href 加版本串；404 立即判定"不支持"并保持静态引用（不再退回 GET，少一次 404）。
  2) 三页里 `boot.js` 的引用**必须去掉 ?v=**（否则 boot.js 自己 404 → 全盘皆输），
     改用 `data-probe="./css/xxx.css"` 指定探测目标。
  3) 底部业务脚本改用 `window.bootScript(src)`（探测失败就用静态地址），
     并加 `else` 分支兜底 boot.js 本身没加载的情况。
- 验证：写了一个"css/js 带 ? 即 404"的模拟服务器 `.workbuddy/tmp/nofresh_server.py`，
  对比两台服务器下三页：8100(不支持) FRESH=false、CSS 静态地址、样式与脚本全部正常；
  8099(支持) FRESH=true、CSS 带时间戳。
- 教训：静态站加版本串前，**先确认服务器认不认 query string**；网关类部署一律要能降级。
- 注意：部署后让用户刷新一次即可（boot.js 的 URL 变了，必然重新拉取）。
